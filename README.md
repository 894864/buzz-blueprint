# Blueprint · 0.1.0-preview.2

Blueprint 是独立的 Buzz API v1 插件，把项目和说明便签放到一页画布，并保存到所选 Buzz 社区的频道中。安装启用后，入口名为 **Blueprint**，位于 Messages、Reminders、Agents 所在的**顶部主导航**。窗口较窄时，Buzz 可能把入口收进导航的更多菜单。

插件不需要修改 Buzz 客户端源码。成员电脑不需要安装 Node、登录 Codex、填写 API Key 或另建服务器；使用已经登录的 Buzz 身份和现有社区服务即可。实际读取、保存能力仍取决于客户端版本、社区服务和当前频道权限。

## 安装与第一次使用

1. 在 Buzz **桌面版**打开头像菜单中的 `Plugins`，或 `Settings → Plugins → Manage plugins`，点击 `Add`，选择 `Git or GitHub repository`。
2. 粘贴 **`https://github.com/894864/buzz-blueprint`**；分支填写 **`main`**。选择仓库根目录中的 Blueprint。Buzz 会直接获取已构建的插件，不需要先下载或解压 ZIP，也不需要 GitHub 账号或原源码仓库权限。
3. 核对插件名称 **Blueprint**，在安装界面确认安装并启用。
4. 打开顶部 **Blueprint**，先选择共享频道，再打开已有蓝图，或点击「新建蓝图」。同事安装后，选择**同一社区、同一频道、同一张蓝图**即可读取共享内容。

每位成员都需要在自己的 Buzz 桌面版确认安装一次；浏览器版不能安装外部插件。在线导入需要电脑已安装 Git，并且 Buzz 能访问 GitHub。社区管理员无法替其他成员静默安装插件。

该公开仓库仅分发插件成品；业务蓝图仍保存在各自选定的 Buzz 社区频道中，不会随插件发布。离线备用方式：从本仓库 Releases 下载 Blueprint ZIP，解压后使用 `Load from folder` 安装；这种来源后续不能直接检查 Git 仓库更新。

### 已经通过 ZIP 或文件夹安装的成员

官方 Buzz 191.1 不能直接替换已保存的安装来源。迁移一次即可：先保存或导出未完成草稿，在插件详情菜单中 `Delete` 旧 Blueprint，然后按上面的 Git 地址重新安装。这里删除的是本机插件，已保存到社区的蓝图和编辑名单仍然保留；重新打开同一社区、频道和蓝图即可。不要删除频道或蓝图内容。

## 导入原来的一页蓝图

先从原应用导出蓝图 JSON，然后在 Blueprint 中选择合适的频道，点击「导入 JSON」。插件会先显示导入草稿；点击「保存草稿」并看到「已保存到社区，并已回读确认」后，它才成为频道中的**一张新蓝图**。

导入创建新的蓝图 ID，不会覆盖已有蓝图。首次保存时，当前登录者成为这张新图的管理员，编辑者名单默认为空。原图、原图的管理员和编辑权限保持原样；重新导入不授予原图编辑权。

导出 JSON 使用字段白名单，保持一页蓝图的 `schemaVersion: 1` 格式，不包含蓝图管理员、编辑者名单、社区记录 ID、修订版本、原分支密码或认证数据。导入不会迁移原应用的账号、分支密码或权限绑定。请使用应用提供的 JSON 导出文件，不要把服务器上的原始数据文件、密码配置或身份文件放进安装包。

**先确定频道成员，再导入业务内容。** 频道访问权限决定谁能读取蓝图；需要隔离的内容应放在成员范围合适的不同频道。蓝图管理员可在本插件里设置编辑者，具体操作见下文。

## 设置谁可以编辑

新建或导入的蓝图首次保存后，默认只有创建者或导入者可以在本插件中编辑。管理员打开该图，点击「编辑权限」，勾选当前频道中允许编辑的成员并保存；未勾选的其他成员默认只读。名单随蓝图保存在社区，其他电脑点击「刷新」获取变化；每次保存内容或名单前，插件都会重新读取当前版本并核对授权。

蓝图管理员与频道管理员分别管理不同事项。只有这张图的管理员能在本插件里修改编辑者名单；授权编辑者能编辑整张图及其中的便签，不能修改名单或转移管理员。便签上的「负责人」不授予编辑权限。Ian 创建或导入的图由 Ian 管理；具备频道写权限的其他成员可以新建或导入自己的图，但不会因此获得 Ian 原图的编辑权限。

这份名单用于团队**防误改**，不是服务器强制的 artifact 安全权限，不能阻止绕过插件的修改。服务器仍按频道规则接受或拒绝写入。不要把编辑者名单当作内容保密或防恶意修改的边界。

旧版已存入社区的 `schemaVersion: 1` 蓝图没有管理员记录，本插件对所有人只读，也不会推测谁是创建者。需要继续编辑时，先导出，再重新导入为新图；首次保存后由导入者管理编辑名单，旧图继续保留。

## 便签与画布操作

| 要做的事 | 操作 |
| --- | --- |
| 拆解项目 | 添加项目，最多支持三级项目；说明便签可以独立存在或关联项目 |
| 移动便签 | 在全图中拖动便签；位置修改会保存到社区 |
| 查看某个分支 | 单击便签，或让便签获得键盘焦点后按 Enter / 空格；顶部路径可返回上级或「全图」 |
| 编辑便签 | 双击便签、按 F2，或使用「编辑便签」；可编辑标题、内容、负责人、状态、进度、旋转及层级 |
| 平移与缩放 | 拖动画布空白处平移；使用画布缩放按钮；画布获得焦点后按 `+` / `-` 缩放、`F` 适合窗口、Escape 返回全图 |
| 查找内容 | 使用搜索，按标题、内容或负责人名称查找便签 |
| 保留一份副本 | 点击「导出 JSON」；存在编辑内容或未保存修改时，使用「导出草稿」 |

聚焦只调整当前电脑上的浏览布局，显示所选便签及直接下级、关联说明，**不改写共享坐标**。回到全图后仍使用原来的排列。聚焦状态下不能通过拖动修改共享位置。

添加、移动、编辑、折叠和删除会提交到社区。删除项目时会连同下级项目删除，界面会先显示确认内容；关联说明会保留并解除关联。便签上的「负责人」只是显示名称，不会授予权限或发送通知。

## 保存、刷新与冲突

**当前版本通过「刷新」获取他人的修改，不是实时多人白板。** 当前托管服务未公布 artifact 实时同步能力；成员修改后，其他人需要点击「刷新」。

保存时，插件会检查打开时的版本是否仍为服务器当前版本，并用 `prev` 版本条件提交。只有把本次签名版本重新读回、确认它已成为当前版本后，才显示「已保存」。发生冲突时，插件保留当前页面草稿，不会悄悄覆盖别人的修改。

遇到冲突或保存结果未确认时：

1. 先点击「导出草稿」，保留本次内容。
2. 刷新前按界面提示确认是否放弃本地草稿，再读取社区最新版本。
3. 对照导出的草稿合并需要保留的修改。重新导入 JSON 会创建新蓝图，不会自动合并到原蓝图。

在当前页面会话内，保存结果不确定时会复用同一个已签名事件重试；插件不会在后台自动发布。**离开 Blueprint、切换社区或账号、关闭 Buzz 之前，必须保存并确认成功，或导出未完成草稿。** 未完成草稿没有持久保存保证；导出也不等于已经上传到社区。

离线时只能查看当前已打开的内容并导出，不能承诺读取其他蓝图或保存修改。

## 数据位置与权限

每张蓝图作为结构化 JSON artifact（类型 `opcb.blueprint.board`，事件 kind `45010`）保存于所选社区和频道。它不占用或覆盖频道的原生 Canvas。

读取受频道访问权限控制。写入前，插件重新核对成员资格、频道可写状态以及 owner / admin / member / bot 角色，并重新读取该图的管理员和编辑者名单。两项检查都通过后才能在本插件中保存；guest / unknown 角色当前只读。频道可写的成员可以创建自己的新图，编辑已有图还需得到该图管理员授权。

新的社区记录使用 `schemaVersion: 2` 外壳保存 `board` 和 `access`；`access.admin` 记录首次保存者，`access.editors` 记录管理员选定的成员。内部 `board` 和导出的 JSON 仍为 `schemaVersion: 1`。授权随该张蓝图保存，不改变频道角色，也不构成服务器 ACL。

插件只通过 Buzz 宿主管理的读取、签名和发布接口工作，不索取或导出 Identity Key、Codex 登录凭据，也不申请文件系统或进程权限。插件安装包仅包含程序；成员间的数据共享来自社区服务，不靠传递安装包或本机文件。

## 当前范围与限制

- 每张蓝图最多 **500 张便签**，包含编辑名单的存储 JSON 最多 **128 KiB**；完整签名事件还必须符合宿主大小上限。
- 导入文件最大 **2 MiB**，并且解析后的蓝图仍需满足上述便签数量和 JSON 容量限制。超限会直接拒绝，不会截断内容；较大的蓝图需要拆成多张。
- 本版支持项目、说明、三级层级、聚焦、排列、状态、进度、负责人名称、搜索、JSON 导入导出及每图编辑者名单。
- 编辑授权按整张蓝图生效，最多记录 100 位编辑者；不提供单便签或分支授权、管理员转移、整张蓝图删除、artifact 跨频道移动、原分支密码管理、自动迁移或实时协同编辑。
- 实际安装、读写验证和完整 CI 的完成情况以对应发布说明为准；本文不代替验收记录。

## 后续升级

从上述 Git 地址、`main` 分支安装后，在 Buzz 的 Blueprint 插件详情中点击 **`Check for updates`**。有新版时点击 **`Update`**，核对并确认；不需要下载 ZIP、解压或重新选择文件夹。请保留 `main` 作为更新来源；固定到某个版本标签的安装不会跟随之后的版本。

插件固定 ID 为 **`opcb.blueprint`**；更新包应保留该 ID，不能仅凭显示名称判断是否为同一个插件。更新会保留启用状态；先保存或导出未完成草稿再更新。

安装包不会自动静默更新。业务数据的读取与保存不需要重新安装插件；其他成员的内容修改通过「刷新」获取。

## 开发与发布记录

源码位于 `extensions/opcb-blueprint/`，生成目录为已被 Git 忽略的 `dist-plugins/opcb-blueprint/`。在仓库根目录执行：

```sh
node extensions/opcb-blueprint/build.mjs
node --test tests/integration/blueprint-plugin.test.mjs
```

构建脚本没有外部依赖，将模块和局部样式合并为自包含的 `plugin.js`。安装目录包含 `manifest.json`、`plugin.js`、`README.md`、`NOTICE.md`；ZIP 只打包这些交付文件，不包含环境变量、业务蓝图导出或个人运行配置。Buzz 安装插件时不执行构建脚本。

API 契约对照来源：

- 官方 Buzz `0.7.0-preview.191.1`，提交 [`fea9f6abf1a85d2a08d3230a80e2e9d5097172a5`](https://github.com/block/buzz-app/tree/fea9f6abf1a85d2a08d3230a80e2e9d5097172a5)。
- 顶部入口使用 API v1 的 page contribution：`primary: true`、`placement: "topbar"`，名称为 `Blueprint`；共享数据通过宿主 `session.snapshotRead` 和 `session.configArtifactWriter` 访问。

插件的 35 项行为测试和 4 项 CI/打包检查已在本机通过。候选已通过官方 Windows Buzz `0.7.0-preview.191.1` 支持的 Update 界面安装；浅色主题、1202×802 窗口中的工具栏和展开后的频道菜单已实看确认布局紧凑。

在仅含一个测试账号的私有频道，已实际完成新建蓝图并保存回读、显示管理员及 0 位授权编辑者、打开权限面板、保存空编辑者名单并回读、添加测试便签并保存回读。手动刷新后，便签标题、正文、状态及管理员与名单显示一致。

真实多账号授权与跨成员读取、深色主题及放大文本尚未完成。单账号验证不代表多人协作已通过验收。每个版本的实际 CI、安装和发布结果见对应 Release 与 PR。

Blueprint 使用独立插件发布流程，登记在 `.opcb-panel-ci.json` 与 `.github/workflows/blueprint-plugin.yml`，仅适用于 `codex/ian-blueprint-plugin` 分支及明确限定的插件、测试和 CI 文件。该范围经授权以插件完整检查、ZIP 校验及官方 Windows Buzz 实测作为发布依据，不要求重建整个 Buzz 客户端。

发布提交须通过三个 GitHub Actions 检查：`Blueprint complete checks and ZIP`、`Blueprint complete hook regressions`、`Blueprint same-run artifact readback`。流程使用仓库固定工具和锁文件，运行全部插件/CI测试及完整 hooks/icons 回归，然后独立下载同次运行产物，对照同一提交重新构建并逐文件核对 ZIP。构建统一 LF 换行，避免 Windows 与 Linux 输出不同。其他分支沿用原检查；正常提交 hooks 继续执行，推送成功不等于 CI 已通过。

使用独立的 `blueprint-v…` 预发布标签，并设置 `latest=false`，保留现有客户端 Release、版本号和 Gitee 更新通道。PR 和发布说明分别记录源码提交、检查、安装与社区读写证据，不把其他 head 或客户端的结果当成本插件验收。
